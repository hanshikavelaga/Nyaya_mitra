# ⚖️ NyayaMitra AI
### *Citizen Legal Shield & Accessibility Platform*

> **"The law is equal for all — but understanding it shouldn't require a law degree."**

NyayaMitra AI was built with a single, powerful purpose: to make Indian legal notices understandable for every citizen, regardless of their legal background. Whether you've received a court summons, a bank recovery notice, a cheque bounce demand, or an eviction warning — NyayaMitra reads it, explains it in plain language, tells you your rights, drafts your reply, and reminds you of your deadlines. All in English or Telugu.

## 🧩 The Problem We're Solving

India has over 40 million pending cases in its judicial system. A significant portion of legal disputes escalate not because citizens lacked a valid defense, but because they:

- **Could not understand** the legalese in the notice they received
- **Missed response deadlines** because the notice dates were buried in dense paragraphs
- **Couldn't afford** a lawyer for an initial assessment
- **Didn't know their rights** under the specific law the notice cited

This is especially acute for citizens from Tier 2 and Tier 3 cities, and for Telugu-speaking communities who receive notices drafted entirely in English.

**NyayaMitra AI directly addresses all four of these gaps.**

---

## 🎯 What NyayaMitra Does

When a citizen uploads a legal notice:

1. The document is **OCR-extracted** locally (for PDFs) or sent to an AI model for multimodal vision analysis (for images)
2. A **structured JSON analysis** is generated by Google Gemini — covering plain-language summaries, extracted deadlines, matched statutory law references, a procedural action checklist, and a ready-to-send response letter
3. Everything is **stored in a local SQLite database** and tied to the citizen's account
4. The citizen can **chat with an AI assistant** that is grounded in the specific document context and matched laws — not generic responses
5. Legal deadlines are **converted into `.ics` calendar files** downloadable to Google, Outlook, or Apple Calendar
6. The entire experience is available in **English and Telugu**, switching in real time

## 🚀 Key Features — Deep Dive

### 📂 Multimodal Document Ingestion

NyayaMitra accepts legal notices in three forms:

| Input Type | How It's Processed |
|---|---|
| **PDF file** | Text extracted locally by `pypdf` (no file sent to network for PDFs) |
| **PNG / JPEG image** | Encoded as base64, sent to Gemini for multimodal OCR |
| **Spoken / typed text** | Plain text string sent directly as the document context |

The upload endpoint (`POST /api/upload`) handles all three paths intelligently. For PDFs, the locally extracted text is prepended to the AI prompt, reducing token cost and latency while keeping sensitive document content more private.

---

### 📑 The Five-Tab Analysis Workspace

After upload, the frontend presents a rich, tabbed workspace. Each tab surfaces a different AI-generated layer of the analysis:

#### Tab 1 — 📋 Summary
A **10–15 line structured plain-language explanation**, always divided into three clearly labelled sections:

- **Notice Overview & Claim Details** — Who issued the notice, what they claim, for how much, and since when
- **Statutory Citations & Citizen Rights** — Which acts apply, what those acts actually say, and what legal protections the citizen has
- **Recommended Legal Strategy** — Concrete options: dispute, negotiate, settle, file a counter, or engage an advocate

The AI is explicitly instructed to avoid legalese and write as if explaining to a first-generation litigant.

#### Tab 2 — ⚖️ Laws & References
A list of **matched statutory law citations**, each with:
- The exact cited section and act name
- A citizen-friendly one-paragraph explanation of what that law actually means
- These are **RAG-retrieved** from the live SQLite laws database (see [RAG Engine](#-the-rag-engine--laws-knowledge-base) below)

#### Tab 3 — ✅ Checklist
Step-by-step **procedural action items** the citizen should take, ordered by priority. These are generated by the AI based on the document type and extracted deadlines.

#### Tab 4 — ✍️ Response Draft Editor
The most powerful tab. NyayaMitra generates a **30–40 line formal legal response letter** with:
- Proper formal headings (Recipient address, date, subject line with case/reference numbers)
- Formal salutation and section-by-section denial of allegations
- Facts in defense with counter-statutory citations
- Formal request for withdrawal or clarification
- Reservation of legal rights clause
- Sign-off with placeholder fields (`[Your Name]`, `[Your Address]`, `[Contact Phone]`)

The editor is **fully editable** inside the browser, with three additional tools:
- **Fullscreen/Compress Toggle** — expands the editor to an absolute fullscreen canvas for focused writing
- **PDF Export** — triggers a styled legal letterhead print-to-PDF download via the browser's native print dialog
- **One-click Clipboard Copy** — copies the entire letter with a toast confirmation alert

#### Tab 5 — 💬 Nyaya Chat
A **context-aware AI chatbot** that is grounded in:
1. The specific document the citizen uploaded (filename, type, raw extracted text)
2. The matched laws from the RAG retriever

This means answers are document-specific, not generic. Every user message and AI reply is **persisted to the `chat_logs` table** in SQLite, so the conversation history is maintained across sessions.

---

### 🗓️ Milestone Tracking & Calendar Reminders

The AI extracts **all legal deadlines** from the notice and classifies them by urgency:

| Urgency Level | Example |
|---|---|
| **High** | Court hearing appearance date (cannot be missed) |
| **Medium** | Written defense filing deadline (30-day window) |
| **Low** | Optional response window or informational date |

Each deadline can be downloaded as a standard `.ics` calendar file via `GET /api/calendar`. These files open directly in Google Calendar, Microsoft Outlook, and Apple Calendar — adding the deadline as a reminder event.

---

### 🔊 Text-to-Speech Audio Readouts

Citizens who struggle with reading can listen to their notice summary. NyayaMitra supports **TTS audio playback** of the generated summary text, with play/pause controls in the UI.

---

### 🌐 Bilingual English & Telugu Support

The entire platform supports **real-time language switching** between English and Telugu:

- **With API keys**: Full AI-powered translation using Gemini — "Translate the following text into clear, citizen-friendly Telugu. Preserve formatting, spacing, names, and key numbers."
- **Without API keys**: Falls back to a carefully curated **static English-to-Telugu dictionary** covering all key UI strings and notice-specific terminology, so the demo mode is still meaningful

The chat endpoint also dynamically detects the user's selected language and instructs Gemini to reply directly in Telugu when needed.

## 🤖 How the AI Pipeline Works

Understanding how NyayaMitra transforms a raw scanned legal document into a structured analysis is key to appreciating the system design.

### Step 1 — File Ingestion & Preprocessing

```
User uploads file (PDF / PNG / JPEG)
          │
          ├── If PDF ──► pypdf extracts text locally
          │              (raw_text_preview is populated before any network call)
          │
          ├── If Image ──► file bytes read as-is, base64 encoded later
          │
          └── If Spoken Text ──► string encoded as UTF-8 bytes
```

Extracting PDF text **locally with pypdf** is a deliberate design decision. It means the raw content of a sensitive legal document is not sent as a raw file attachment over the internet — only the extracted text string goes to the AI. For images, the bytes must be sent for vision-based OCR.

### Step 2 — RAG Grounding (Before AI Call)

Before calling any AI model, the system runs its **Retrieval-Augmented Generation (RAG)** step:

```
Filename + raw_text_preview
          │
          ▼
tokenize_text() — lowercases, strips punctuation, splits into word tokens
          │
          ▼
For each law in SQLite laws table:
  - Score = number of keyword tokens that overlap with the document tokens
  - Multi-word phrases ("cheque bounce") get weight × 3 (exact phrase match)
          │
          ▼
Top 2 highest-scoring laws are selected
(Falls back to first law in DB if no overlap found)
          │
          ▼
Matched laws JSON injected into the AI prompt as grounding context
```

This means the AI response is always **anchored to real, relevant Indian statutes** that match the document content — not hallucinated references.

### Step 3 — The AI Prompt

The AI receives a precisely engineered prompt (`PROMPT_TEMPLATE`) that instructs it to output a **single JSON object** with strict fields:

```json
{
  "raw_text": "verbatim OCR text",
  "summary": "10-15 line multi-paragraph plain-language explanation",
  "document_type": "classified category (e.g. Section 138 Notice)",
  "extracted_dates": [
    { "title": "...", "date": "YYYY-MM-DD", "urgency": "High/Medium/Low" }
  ],
  "legal_references": [
    { "section": "...", "description": "citizen-friendly explanation" }
  ],
  "checklist": ["action item 1", "action item 2", ...],
  "response_template": "Full 30-40 line formal legal letter draft"
}
```

The prompt explicitly instructs the model to:
- Divide the summary into three labelled paragraphs (Overview, Statutory Citations, Legal Strategy)
- Write the response template with formal legal headings and a "reservation of legal rights" clause
- Include placeholder fields like `[Your Name]` for the citizen to fill in

### Step 4 — Storage

All AI-generated fields are stored in the `documents` SQLite table. JSON arrays (dates, laws, checklist) are serialized as JSON strings. This means the analysis is **persistent** — the citizen can return to view their notice any time without re-running the AI.

### Step 5 — Response Return

The backend returns a structured JSON payload to the frontend with all five analysis layers populated. The frontend then renders them across the five tabs.

## 📚 The RAG Engine — Laws Knowledge Base

NyayaMitra maintains a **curated statutory laws database** seeded from `backend/data/laws_kb.json` on first startup. This is the backbone of the legal grounding system.

### What the Laws Table Contains

Each law record has:

| Field | Description |
|---|---|
| `act` | Full name of the act/section (e.g. "Section 138 of the Negotiable Instruments Act, 1881") |
| `category` | Legal category (e.g. "Banking & Finance", "Property", "Consumer") |
| `scope` | Jurisdiction / applicability |
| `summary` | 2-3 sentence citizen-friendly summary |
| `details` | Full detailed explanation |
| `remedies` | JSON array of actionable remedies available to the citizen |
| `keywords` | JSON array of trigger words/phrases used for RAG matching |

### How RAG Matching Works

The retriever uses **keyword overlap scoring** — a deliberately lightweight approach chosen for:
- **Zero dependency** on vector databases or embedding APIs
- **Instant results** — no network call or index lookup
- **Transparent logic** — a developer can read exactly why a particular law was matched

Multi-word phrases (like `"cheque bounce"`, `"eviction notice"`) receive a **3× weight bonus** over single keyword matches, ensuring contextually specific documents are matched to the most relevant laws even when the terminology is dense.

## 🔐 Authentication System

NyayaMitra supports two distinct authentication strategies, both producing a standard **JWT Bearer token** on success.

### Strategy 1 — Email + Password with OTP Verification

```
User fills sign-up form (name, email, password)
          │
          ▼
POST /api/auth/send-email-otp
  → Generates a cryptographically random 6-digit OTP
  → Stores it in the email_otp_codes table with a 10-minute expiry
  → If SMTP_USERNAME + SMTP_PASSWORD are configured:
       Sends a styled HTML email (dark background, indigo OTP box)
  → If SMTP is not configured:
       Logs OTP to server console (dev mode)
          │
User enters OTP in the UI
          │
          ▼
POST /api/auth/verify-email-otp
  → Validates OTP against DB, checks expiry
  → Creates user record with bcrypt-hashed password
  → Returns JWT access token
          │
Future logins: POST /api/auth/login (email + password → JWT)
```

### Strategy 2 — Phone Number + SMS OTP via Twilio

```
User enters phone number
          │
          ▼
POST /api/auth/send-otp
  → Generates 6-digit OTP, stores with expiry
  → If TWILIO credentials are set:
       Twilio REST API sends SMS via from_ number
  → If no Twilio credentials:
       OTP logged to server console (dev mode)
          │
User enters received OTP
          │
          ▼
POST /api/auth/verify-otp
  → Validates OTP + expiry
  → If user doesn't exist: creates new account
  → If user exists: logs in
  → Returns JWT access token
```

### JWT Token Security

- Tokens are signed with **HS256** using `python-jose`
- Protected routes extract the token from the `Authorization: Bearer <token>` header
- The `verify_access_token()` service function validates signature and expiry
- Authenticated user ID is extracted from the `sub` claim and used for all document association

## 🗄️ Database Design

NyayaMitra uses **SQLite** via SQLAlchemy ORM. The database is automatically created at `backend/data/nyayamitra.db` on first startup. All tables are defined in `backend/models.py`.

### Entity Relationship Overview

```
users ─────────────────────────────────────────┐
  │ id, full_name, email, phone_number,        │
  │ password_hash, auth_provider, created_at   │
  │                                            │ one-to-many
  └───► documents ──────────────────────────── ┘
           │ id, user_id (FK), filename,
           │ doc_type, raw_text,
           │ summary_explanation,
           │ extracted_dates_json,          JSON strings
           │ legal_references_json,         stored as TEXT
           │ checklist_json,
           │ response_template,
           │ uploaded_at
           │
           └───► chat_logs
                    id, document_id (FK),
                    role ('user'/'assistant'),
                    content, created_at

laws (standalone, seeded from laws_kb.json)
  id, act, category, scope, summary,
  details, remedies_json, keywords_json

otp_codes       → phone-based OTP (phone_number, otp, expires_at)
email_otp_codes → email-based OTP (email, otp, expires_at)
```

### Database Resilience

The `safe_commit()` function in `database.py` retries database commits up to **5 times with 1-second intervals** when SQLite raises a "database is locked" error. This handles scenarios where external tools like DB Browser for SQLite have the database file open simultaneously.

## ⚡ Getting Started — Full Setup Guide

### Prerequisites

Before you begin, make sure you have the following installed:

- ✅ **Python 3.8 or higher** — `python --version`
- ✅ **Node.js 18 or higher** — `node --version`
- ✅ **npm** — `npm --version`
- ✅ **Git** — `git --version`

You will also optionally need:
- 🔑 A **Google Gemini API key** or an **OpenRouter API key** (for real AI analysis)
- 📱 A **Twilio account** (for SMS OTP login)
- 📧 An **SMTP email account** like Gmail App Password (for email OTP)

> **Don't have API keys?** No problem. The app runs fully in **Demo/Mock Mode** — see [Running in Demo Mode](#-running-in-demo-mode-no-api-keys).

### Clone the Repository

```bash
git clone https://github.com/hanshikavelaga/Nyaya_mitra.git
cd Nyaya_mitra
```

### Backend Setup

#### 1. Navigate to the backend folder
```bash
cd backend
```

#### 2. Create and activate a virtual environment
```bash
python -m venv venv
```

Activate it:
```bash
# Windows PowerShell:
.\venv\Scripts\Activate.ps1

# Windows Command Prompt:
venv\Scripts\activate.bat

# macOS / Linux:
source venv/bin/activate
```

You should see `(venv)` appear in your terminal prompt.

#### 3. Install all Python dependencies
```bash
pip install -r requirements.txt
```

#### 4. Create your `.env` file

Create a new file called `.env` inside the `backend/` directory. See the full [Environment Variables Reference](#-environment-variables-reference) below for all options.

At a minimum, create an empty `.env` for demo mode:
```bash
# Windows:
type nul > .env

# macOS / Linux:
touch .env
```

#### 5. Start the backend server
```bash
python -m uvicorn main:app --reload --port 8000
```

You should see output like:
```
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO:     Started reloader process
INFO:     Database laws table is empty. Seeding from laws_kb.json...
INFO:     Successfully seeded X laws into SQLite database.
```

The backend is now running. The SQLite database is created automatically and the laws knowledge base is seeded on first startup.

> **Tip:** You can explore the auto-generated interactive API docs at `http://localhost:8000/docs`

### Document Processing

#### `POST /api/upload`
Ingests a legal notice, performs AI analysis, and persists results.

**Request** (`multipart/form-data`):

| Field | Type | Required | Description |
|---|---|---|---|
| `file` | File | No* | PDF, PNG, or JPEG file (max 10MB) |
| `spoken_text` | string | No* | Plain text description of the notice |
| `notice_type` | string | No | Hint for document classification |
| `user_id` | integer | No | User ID for linking document to account |
| `Authorization` | Header | No | `Bearer <token>` — preferred over `user_id` |

*Either `file` or `spoken_text` must be provided.

**Response** (200):
```json
{
  "document_id": 42,
  "filename": "eviction_notice.pdf",
  "doc_type": "Eviction Notice",
  "raw_text": "verbatim OCR text...",
  "uploaded_at": "2026-07-30T10:00:00",
  "analysis": {
    "summary": "Plain language explanation...",
    "extracted_dates": [{"title": "...", "date": "YYYY-MM-DD", "urgency": "High"}],
    "legal_references": [{"section": "...", "description": "..."}],
    "checklist": ["Step 1...", "Step 2..."],
    "response_template": "Full legal response letter..."
  }
}
```

> **Note:** An SMS notification is also sent after successful upload (to the configured number, or logged to console in dev mode).

---

### Chat

#### `POST /api/chat`
Context-aware AI chat grounded in a specific uploaded document.

**Request** (JSON):
```json
{
  "message": "What is the deadline I need to respond by?",
  "document_id": 42,
  "history": [
    {"role": "user", "content": "previous question"},
    {"role": "assistant", "content": "previous answer"}
  ],
  "language": "english"
}
```

**Response** (200):
```json
{
  "document_id": 42,
  "reply": "Based on your document and Section 138...\n\n---\n*Disclaimer: ...*"
}
```

All messages (user + assistant) are persisted to the `chat_logs` table.

### Laws Database

#### `GET /api/laws`

#### `GET /api/laws/categories`

### Calendar

#### `GET /api/calendar`
Generates a standard RFC 5545 `.ics` calendar file for a single deadline.

**Query params**: `?date=2026-09-05&title=Court+Hearing`

**Response** includes `ics_file_content` string that the frontend downloads as a `.ics` file.

## 🧪 Running in Demo Mode (No API Keys)

NyayaMitra is fully functional **without any API keys**. This is intentional — it allows development, testing, and demonstrations without spending API credits.

### What happens in Demo Mode:

| Feature | Demo Mode Behavior |
|---|---|
| **Document upload (PDF)** | Text extracted locally, then matched against mock data templates |
| **Document upload (image)** | Rich pre-written analysis loaded based on filename keywords |
| **AI analysis** | Realistic multi-paragraph analysis from curated templates covering: eviction notices, cheque bounce (S.138), DRT court summons, and default notices |
| **Nyaya Chat** | Contextual mock response referencing matched law and document filename |
| **Translation** | Static English-to-Telugu dictionary covering all key UI strings |
| **Email OTP** | OTP printed to server console (`VERIFICATION CODE: 123456`) |
| **SMS OTP** | OTP printed to server console |

**The mock templates are rich and realistic** — they include full DRT summons text, cheque bounce demand notices, court order details, actual Indian statutory citations, and complete formal legal response letters. A demo using these templates is indistinguishable from a real AI response for presentation purposes.

### Running demo:
```bash
# backend/.env — leave it empty or don't create it at all
# Then start normally:
python -m uvicorn main:app --reload --port 8000
```
